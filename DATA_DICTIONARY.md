# Data Dictionary — Canonical Fields

Authoritative definitions of canonical fields. Table layout: [DATABASE_DESIGN.md](DATABASE_DESIGN.md). Adapter-specific source mappings: [DATA_INGESTION.md](DATA_INGESTION.md#4-source-adapters).

## 1. Conventions

**Category** (always shown in the API and UI so users can tell facts from inferences):

| Category | Meaning |
|---|---|
| **R — Raw** | Exactly as received from the source (possibly as text). |
| **N — Normalised** | Observed value converted to canonical type/format; no inference. |
| **D — Derived** | Computed deterministically from R/N values (hashes, keys, ratios). |
| **M — Model output** | Produced by a statistical/ML model. A prediction, not an observation. |
| **H — Hypothesis** | Produced by correlation rules; to be reviewed. |
| **A — Analyst conclusion** | Entered by a human reviewer. |

**Required (Req):** `Y` required for every event; `C` conditionally required (by `event_type`, stated in Validation); `N` optional.

**Examples** use documentation IP ranges (RFC 5737: `192.0.2.0/24`, `198.51.100.0/24`, `203.0.113.0/24`) and fictional names.

**Source** column: `adapter` = mapped by the ingestion adapter; `system` = generated by the platform; `dataset` = provided by a labelled dataset; `model`; `rule`; `analyst`.

## 3. Security event fields

### 3.1 Time

| Field | Type | Req | Cat | Meaning | Validation | Source | Example |
|---|---|---|---|---|---|---|---|
| `event_time` | timestamptz | Y | N | When the event started/occurred, UTC. | 2000-01-01 ≤ t ≤ now + 24 h (the `dim_date` range starts 2000-01-01). Naive input interpreted in the source's `default_timezone`. | adapter | `2017-07-05T13:42:10Z` |

### 3.3 Flow metrics

Directions: **out** = from source/originator to destination; **in** = from destination back to source. Byte semantics differ by source (payload vs. IP-level); the adapter documents which is used.

| Field | Type | Req | Cat | Meaning | Validation | Source | Example |
|---|---|---|---|---|---|---|---|
| `duration_s` | double | N | N | Flow duration in seconds. | Finite, ≥ 0. | adapter | `1.503` |
| `bytes_out` | bigint | N | N | Bytes source → destination. | ≥ 0. | adapter | `2048` |
| `bytes_in` | bigint | N | N | Bytes destination → source. | ≥ 0. | adapter | `512` |
| `packets_out` | bigint | N | N | Packets source → destination. | ≥ 0. | adapter | `12` |
| `packets_in` | bigint | N | N | Packets destination → source. | ≥ 0. | adapter | `9` |

Ratios such as bytes/packet and packets/second are **derived features** computed in feature engineering ([ML_CLASSIFICATION.md](ML_CLASSIFICATION.md#4-feature-selection)), not stored columns.

## 7. Anomaly outputs (model)

| Field | Type | Cat | Meaning | Interpretation | Example |
|---|---|---|---|---|---|
| `entity_type` / `entity_value` | text | D | Entity scored (`host`, `account`, `src_ip`). | — | `account` / `alice` |
| `window_start` / `window_end` | timestamptz | D | Feature window. | — | |
| `anomaly_score` | double | M | Method-specific score, **higher = more unusual**. Isolation Forest: negated `score_samples`. Robust z: max absolute robust z across features. | **Not a probability.** Comparable only within the same model version. | `0.61` |

| `threshold` | double | D | Threshold in force when scored. | — | `0.58` |
| `is_flagged` | boolean | M | `anomaly_score ≥ threshold`. | Unusual ≠ malicious. | `true` |
| `top_deviations` | jsonb | D | Features contributing most, with value vs. baseline. | Explanation aid. | `[{"feature":"failed_auth_count","value":57,"baseline_median":2}]` |

## 11. Enumerations

### 11.1 `event_type`

`network_flow`, `ids_alert`, `auth`, `endpoint_process`, `endpoint_file`, `endpoint_network`, `dns`, `http`, `other`.

### 11.2 `attack_category`

| Code | Description | `is_benign` |
|---|---|---|
| `BENIGN` | Normal/background traffic as labelled by the dataset. | yes |
| `DOS` | Denial of service from a single/limited source. | no |
| `DDOS` | Distributed denial of service. | no |
| `RECONNAISSANCE` | Scanning, probing, enumeration. | no |
| `BRUTE_FORCE` | Credential guessing (e.g., SSH/FTP brute force). | no |
| `WEB_ATTACK` | Web application attacks (injection, XSS, web brute force). | no |
| `BOTNET` | Bot command-and-control / bot traffic. | no |
| `INFILTRATION` | Post-compromise internal activity as labelled by the dataset. | no |
| `EXPLOIT` | Exploitation of a vulnerability. | no |
| `BACKDOOR` | Backdoor access traffic. | no |
| `SHELLCODE` | Shellcode delivery. | no |
| `WORM` | Self-propagating malware traffic. | no |
| `FUZZING` | Fuzzing traffic. | no |
| `ANALYSIS` | UNSW-NB15 "Analysis" category (port scans, spam, HTML penetration as described by the dataset). | no |
| `GENERIC` | UNSW-NB15 "Generic" category (dataset-defined). | no |
| `OTHER_MALICIOUS` | Malicious labels merged due to low support or no closer category. | no |

### 11.3 Entity types

`host`, `account`, `src_ip`, `dst_ip`, `domain`.

### 11.4 Workflow statuses

- Alert: `new`, `acknowledged`, `in_review`, `escalated`, `dismissed`, `closed`.
- Case: `open`, `investigating`, `closed` (+ `disposition` on close).
- Job: `queued`, `running`, `succeeded`, `failed`, `cancelled`.
- Model: `candidate`, `active`, `archived`, `rejected`.
